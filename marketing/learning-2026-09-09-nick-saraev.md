## 2. 강의의 다섯 기능을 글링에 번역한 결과

| 강의의 기능 | 해결하는 문제 | 글링의 적용 | 현재 판단 |
|---|---|---|---|
| 광고·이미지·영상 제작 | 소재 제작의 반복 비용 | 실제 앱 화면에 근거한 SNS 원고와 소수 후보 | 채택. 대량 생성보다 사실·규격·도착 경로 검수 우선 |
| 맞춤 문구 | 사람마다 다른 상황에 맞춘 설명 | 밴쿠버·토론토, 동네 질문·모임 등 확인된 맥락 | 채택. 이름 치환·가짜 경험 대신 실제 맥락 |
| 빠른 문의 응답 | 관심을 보인 사람을 다음 행동으로 연결 | 출시 전 앱 소개, 출시 후 설치·첫 이용; 지원 문의 분리 | 수정 채택. 상담·전화 예약 중심 구조는 맞지 않음 |
| 데이터 수집·대시보드 | 무엇이 막혔는지 파악 | 게시·유입·신청·설치·첫 이용·재방문을 분리한 근거 기록 | 채택. 현재 없는 자료는 미확인 |
| 후속 연락 | 상태에 맞는 다음 조치 | 실제 질문·문제 해결·요청한 출시 알림에 대응 | 조건부 채택. 청구서 추심·대량 콜드메일 흐름은 보류 |

강사의 고객은 주로 마케팅 자동화를 사는 사업자다. 글링의 고객은 지역 대화와 만남을 원하는 개인이다. 사업자를 상담으로 연결하는 방식 전체를 복사하면 글링 사용 전에 이메일·예약 단계를 늘리게 된다. 사용자가 원한 **바로 써볼 수 있는 흐름**을 기준으로 바꾸었다. 현재 공개 설치가 준비되지 않았으므로 설치를 약속하지 않고 앱 화면 소개를 먼저 안내한다.

**반영:** 시작 문서와 글링 폴더를 고정하고 계정·필요 기능을 실제 환경에서 점검한다. 읽기/예약/발행/성과 조회 능력을 따로 확인하도록 했다. 오래된 도메인이 남아 있던 제품 컨텍스트도 현재 주소로 정정했다. 대화 기억에만 의존하지 않도록 프로젝트 AGENTS.md에서 실행 지침을 연결했다.

**반영:** 대화 이력이 없는 회차용 실행 지시를 `launch-kit.md`에 저장했다. 로컬 준비 회차를 먼저 실행했고, SNS 계정이 없는 상태에서 무의미한 정기 작업을 새로 만들지 않았다. 첫 실제 운영 후 단일 Orca 예약으로 반복한다는 기준을 남겼다.

### 07. 광고 스킬·반복 작업·클라우드 및 이미지 생성 · 1:42:53–2:35:08

[원영상 1:42:53](https://www.youtube.com/watch?v=yulWjh3rq28&t=6173s) · 자막 405구간

**확인:** 수량·일정·출력 위치를 구체화하고 날짜별 결과를 저장한다. 로컬 작업을 클라우드로 옮길 때 중복 실행 제거, Drive 권한, 별도 인증, 실제 업로드 확인이 필요하다. 이미지 생성에서는 입력 형식, 모델 선택, 제품 참조와 구성 보존에 여러 번 수정이 들어간다. 자유도가 높아지자 원래 의도한 광고 구성이 달라진다.

**분석:** 가장 먼저 필요한 것은 ‘이 환경에서 이 입력으로 결과 한 개를 만들 수 있는가’라는 기능 검증이다. 3개 템플릿 × 5개 후보와 총 5개는 비용과 수량이 다르다. 로컬 인증 성공을 원격 인증 성공으로 간주하면 안 된다. 결과 저장 날짜만으로 재처리 여부를 판단하면 부분 실패와 수정된 입력을 놓친다.

**반영:** 글별 고정 ID와 외부 저장/발행 참조를 추가했다. 작업 수량과 완료 증거를 미리 정하고, 성공한 항목을 제외한 재시도만 한다. 인증 오류는 즉시 원인을 기록한다. 공통 스킬을 전부 호출하거나 생성 서비스 구독을 늘리는 방식은 택하지 않았다.

### 08. AI 영상 광고 제작 · 2:35:08–2:59:15

## 6. GL-L001 — 이번에 실제 반영한 첫 문장 실험

상태: **B 초안 반영 완료 / 예약·발행·관측 전**. 기준은 운영 탐색이며 무작위 A/B 실험이 아니다.

가설은 추상적인 커뮤니티 설명보다 구체적인 지역 상황으로 시작하면 적합한 독자가 글링을 자신의 일과 연결하기 쉽다는 것이다. 고객 데이터에서 확인된 결론이 아니라 시험할 가설이다.

| 요소 | A 후보 | B 후보 — GL-P002에 반영 |
|---|---|---|
| 첫 문장 | 밴쿠버의 오늘을, 한국어로 나눌 곳. | 밴쿠버에서 혼자 밥 먹기 편한 곳, 동네 사람에게 물어볼 수 있다면? |
| 본문 | 아래 공통 본문 | 아래 공통 본문 |
| 주 CTA | 출시 준비 중인 앱 화면 보기 | 동일 |
| 형식 | Threads 텍스트 | 동일 |
| 주요 변경 | 추상적 소개 | 구체적 동네 질문 |

공통 본문:

```text
도시별로 글과 댓글을 나누는 글링을 준비하고 있어요. 먼저 시작하는 도시는 밴쿠버와 토론토예요. 출시 준비 중인 앱 화면은 아래 링크에서 볼 수 있어요.
```

B 초안에는 현재 글링 주소와 `utm_content=gl_p002`를 실제로 넣었다. A를 후속 발행한다면 새 게시물 ID와 해당 ID의 태그를 사용하되 목적지·본문·형식을 같게 한다. 날짜나 독자 구성이 달라질 수 있으므로 순수한 첫 문장 효과로 단정하지 않는다.

- **관측:** 가능한 원본 조회/도달, 실제 관련 댓글, 제공되는 직접 링크 클릭을 게시 후 24h/72h/7d에 기록한다. 원본 지표가 없으면 미확인이다.
- **판단:** 관련 독자의 질문/이동이 확인되면 다음 같은 주제에서 구체적인 상황형을 더 시험한다. 낮은 노출·측정 실패만으로 첫 문장 실패를 선언하지 않는다. 임의의 작은 표본으로 통계적 승자를 정하지 않는다.
- **다음 변화:** 한 회차의 주된 요소는 유지한다. 사용자 최신 제품 판단인 모임·만남 가치는 후속 별도 가설로 다루고 동시에 섞어 성과 원인을 흐리지 않는다.
- **확인 결과:** 저장된 GL-P002 초안과 실제 도착 링크를 점검했다. 신규 고객 반응이나 개선율은 아직 없다.

## 9. 공통 프로세스에 남길 학습

1. 참고 자료는 부분 검토·전체 자막 검토·선택 화면 확인·실습 재현을 구분해 기록한다. 자료를 확보한 것과 읽은 것은 다르다.
2. 좋은 단일 실행을 먼저 만들되, **최종 목적지와 완료 증거부터 역으로** 확인한다. 연결 목록이나 생성 파일은 고객 결과가 아니다.
3. 품질 검수는 마지막 결과물에서 한다. 문구의 변수 한 칸, 이미지 한 장, 예약 버튼 클릭만으로 끝내지 않는다.
4. 대상/작업 ID·실제 외부 참조·미완료 원인·제한된 재시도는 반복 실행의 기본이다. 불확실한 외부 쓰기는 조회 후 판단한다.
5. 지표는 출처·기간·집계 단위·분모를 보존한다. 결측은 0이 아니고 공용 링크 유입은 개별 글 성과가 아니다.
6. 실험은 문서의 아이디어에서 끝내지 않고 다음 원고 ID와 실제 반영 단계까지 연결한다. 성공·실패·판단 보류와 재시도 조건을 누적한다.
7. 같은 원리는 공유하되 사업자 상담, 소비자 설치, 지역 커뮤니티 재방문을 같은 전환으로 취급하지 않는다.
8. 도구 예시·가격·자동화 규모보다 사용자 비용 제한과 실제 고객의 다음 행동이 우선한다.

이 원칙과 글링의 실제 반영·검증 결과를 공통 `marketing-sales-playbook.md`에 갱신했다. 사용자 경험, 강사의 시연, 우리 운영에서 검증한 결과를 구분해 다음 제품에도 적용한다.
