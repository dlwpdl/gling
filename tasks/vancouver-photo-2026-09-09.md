# 콜하버 실사진 게시글

운영 DB의 밴쿠버 피드에 **「이런 날엔 콜하버 한 바퀴」** 한 편을 등록했다. 글 ID는 `20000000-0000-0000-0000-000000000054`이며 전체 시드 글은 54개다. 마이그레이션 0026은 ID 충돌 시 기존 글을 덮어쓰지 않는다.

- 기존 관리용 시드 작성자 `버라드러너`의 활성 상태·안전 분석 동의·L1 등급을 확인했다. 인증 등급과 반응 수를 올리지 않았다.
- [실제 콜하버 사진과 라이선스 기록](../assets/seed/README.md)을 사용했다. 직접 촬영·당일 촬영으로 표현하지 않고 본문에 Vlad D / Unsplash 출처를 남겼다.
- 사진을 기존 비공개 `post-images` 버킷의 작성자 폴더에 업로드했고, 원본과 게스트 다운로드의 SHA-256이 일치했다.
- 기존 안전 처리 트리거가 새 글을 큐에 넣은 것을 확인했다. 업로드·게시를 위해 안전 처리나 동의 검사를 해제하지 않았다.

## 발견한 이미지 접근 문제와 검증

기존 Storage SELECT 정책은 로그인한 사람만 허용해, 비로그인 사용자는 공개 글을 읽어도 첨부 사진 URL을 받지 못했다. 실제 `createSignedUrls` 요청과 RLS 검사에서 재현했다.

0027은 게스트에게 **활성 작성자가 공개한 글의 자기 폴더 첨부 사진**만 읽도록 허용한다. 버킷은 계속 비공개이며 익명 업로드 권한은 추가하지 않는다. [Supabase Storage RLS](https://supabase.com/docs/guides/storage/security/access-control)를 따랐다. 기존 1시간 서명 URL 수명은 유지한다.

`supabase/tests/public_post_images.test.sql`의 5개 검사가 수정 전 공개 사진 읽기에서 실패하고 수정 후 모두 통과했다. 공개 사진은 허용하고, 미게시 업로드·아바타·삭제된 글·비활성 작성자의 사진은 거부한다. 검사는 트랜잭션을 롤백했으며 검사 객체가 남지 않았다.

실제 게스트 클라이언트에서 사진 HTTP 200과 체크섬, 밴쿠버 피드 포함을 확인했다. iOS 26.5·Android API 36의 빌드 6과 웹 상세 화면에서 사진 표시를 확인했다. [iOS 실제 화면](../output/screenshots/gling-vancouver-photo-ios.png).

공유용 Edge Function은 사진을 포함한 HTML을 만들지만 기본 `supabase.co` 호스트의 응답은 `text/plain`으로 내려온다. 공개 공유 미리보기는 도메인·웹 제공 경로 정리 때 함께 해결해야 하며, 이 URL을 완성된 웹 미리보기로 안내하지 않는다.
